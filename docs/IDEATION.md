# Aquagarden — 개선 아이데이션

> 이 문서는 실사용 피드백·원본-현재 비교 분석·세션 중 발견한 개선 후보를 아이데이션 단계로 정리한다.
> 결정 전 탐색 공간이므로, 구현 확정 시 ADR로 전환하고 여기서는 제거한다.
> 마지막 업데이트: 2026-05-22

---

## 1. 미학 회귀 (최우선)

### 배경

원본(`prototype.html`)과 현재 버전을 나란히 놓고 보면 **원본이 더 아름답다는 인상을 준다**.
현재 버전은 ACESFilmic 톤매핑·Bloom·코스틱 등 더 많은 후처리를 갖췄음에도 오히려 탁하고 단조롭게 보인다.

### 외부 평가 (Codex, 2026-05-22)

원본 라이브(`outliner-coach.github.io/aquagarden_gemini_flash_3.5`) vs 현재 빌드를 **이중 축**으로 진단:

| 축 | 우세 | 근거 |
|---|---|---|
| 첫인상 / 순수 미감 | **원본** | 어두운 청록 배경 + 밝은 바닥 + 붉은 물고기 + 분홍 수초가 명확히 분리 → 구도·실루엣이 읽히고 덜 피곤 |
| 제품 방향 / 위젯 적합성 | **현재** | 작은 HUD, 위젯 목적 부합, 코스틱·밀도·포스트FX 등 시네마틱 요소 |
| 최종 목표 근접도 | **현재** | 480×320 상시 위젯엔 원본의 큰 UI 카드가 수조를 가려 "데모 UI"처럼 보임 |
| 지금 당장 예쁜 쪽 | **원본** | 현재는 "과근접 + 탁한 녹색 + 과밀 정글" 인상 |

**핵심 통찰 — 큰 리팩터가 아니라 "감산(減算)"이 답이다.** 현재 빌드는 시네마틱 요소를 *더한* 결과 오히려
시끄러워졌다. 색 온도를 낮추고, 녹색 채도를 줄이고, 카메라를 빼고, 식재를 덜어내면 원본의 깨끗한 첫인상을
되찾으면서 위젯 적합성은 유지할 수 있다. 아래 개선안은 이 "덜어내기" 원칙으로 재정렬한다.

### 진단된 원인

| 파라미터 | 원본 | 현재 | 영향 |
|---|---|---|---|
| 낮 포그 색상 | `0x1a3a40` (어두운 청록) | `0x274320` (중간 녹색) | 배경이 밝고 탁해 깊이감 소실 |
| 낮 포그 밀도 | 0.045 | 0.032 | 포그가 엷어 배경이 훤히 드러남 |
| ambient 색상 | 차가운 계열 | `0xe2e6bc` (따뜻한 연두 크림) | 씬 전체에 노란-초록 캐스트 |
| ambient 강도 | — | 1.05 + topLight 6.0 | 균일한 조명 → 대비 소실 → Bloom이 초록 빛을 번지게 함 |

**핵심 메커니즘**: 포그가 엷으면 배경이 환해지고, 여기에 따뜻한 ambient가 초록 캐스트를 전체에 입힌다.
ACESFilmic + Bloom은 이 캐스트를 증폭시켜 결과적으로 "탁한 연두 연못" 인상이 된다.
원본의 어두운 청록 포그는 조명 광원(topLight 스포트)을 도드라지게 하고, 붉은 베타가 청록 배경에서 강한 대비로 빛났다.

### 개선 아이디어

**A. 포그·배경 어둡게 복귀** ← 가장 빠른 효과
- 낮 포그 색상: `0x274320` → `0x0e2218` 전후 (어두운 청록-그린, 원본 청록에서 약간 그린 유지)
- 낮 포그 밀도: 0.032 → 0.040 ~ 0.045
- 낮 bg: `0x0e2113` → `0x05110a` (더 어둡게)

**B. Ambient 정리**
- 낮 ambient 색상: `0xe2e6bc` → 덜 황록적인 `0xb8cca8` 또는 원본처럼 차가운 방향
- 낮 ambient 강도: 1.05 → 0.85 (topLight·코스틱 대비 살리기)

**C. topLight 강도 조정**
- 현재 6.0은 과하게 밝아 지점 폭파(overexposure) 가능성 → 4.5~5.0으로 내리고 Bloom threshold를 다시 측정

**D. Bloom threshold 재조율**
- 현재 threshold가 낮아 초록 계열 전체에 bloom이 번질 수 있음 → 네온테트라 emissive·코스틱 하이라이트만 잡도록 threshold 상향 (0.92 → 1.05)

**E. 녹색 채도 낮추기** ← Codex "탁한 정글" 진단 (감산)
- `greenish()` base `0x4a7e2e`는 채도가 높아 78+46개가 깔리면 화면을 잡아먹음 → 채도를 한 단계 낮춰
  올리브-세이지 방향(`0x4a7e2e` → `0x5a6e44` 전후)으로. 클램프 범위(`0x3a661f`~`0x60963a`)도 동반 하향.
- 중경 단색 녹색 `0x6fae3f`(라임 톤)도 같은 폭으로 채도 down.
- 위치: [aquascape.ts:380](src/scene/aquascape.ts:380), [aquascape.ts:397](src/scene/aquascape.ts:397).

**F. 빨간 수초 "벽" 분산** ← Codex "덜 뭉치게"
- 적색 줄기수초 62개가 `x 6.5~11.5`의 좁은 5폭에 몰려 단단한 벽을 형성 → ① 개수 62 → 40~46으로 솎고,
  ② x 분포 폭을 넓혀(`6.5 + random()*5` → `5.5 + random()*7`) 좌측 녹색군과 사이에 호흡 공간을 둔다.
- 톤 변주(`0x9c2f2b`/`0xb0432f`)는 유지하되, 일부를 더 어둡게 섞어 벽의 균일감을 깬다.
- 위치: [aquascape.ts:399](src/scene/aquascape.ts:399).

**G. 전경 식재 밀도 덜기** ← Codex "전경 식재 밀도 덜어내기"
- 전경 카펫 40개가 카메라 최전경(`z 1.5~5`)을 빽빽이 채워 시야를 막고 깊이감을 뭉갠다 → 28~32개로 솎고,
  최전경(`z < 2.5`)은 비워 카메라-피사체 사이 "맑은 물" 레이어를 확보.
- 위치: [aquascape.ts:408](src/scene/aquascape.ts:408).

**검증 방법**: 수정 후 `node scripts/capture-framing.mjs`로 5개 비율 캡처 → AESTHETIC 루브릭 → 사용자 사인오프.
원본 라이브를 동일 비율로 나란히 두고 "첫인상 깨끗함"을 직접 대조한다.

## 2. 카메라 구도

### 문제
"기질을 화면 하단에 고정" 프레이밍이 가로 비율에서 갈색 기질을 화면 아래 25~30%에 깔아두고, 위쪽은 비어 있는 초록 물만 넓게 보인다. 식재부와 물고기가 하단에 몰리는 인상.

### 아이디어

- **카메라 5~10% 뒤로** ← Codex "과근접" 진단. 현재 거리는 `HERO_W=20` cover로 산출되고 `MAX_DISTANCE=D_NORMAL`로 클램프 → `HERO_W`를 21~22로 키우거나 산출 거리에 ×1.05~1.10을 곱해 한 발 빼면 과밀 정글이 한눈에 정돈된다. 위치: [framing.ts:16](src/scene/framing.ts:16), [framing.ts:34](src/scene/framing.ts:34).
- **`FRAME_BOTTOM_Y` 올리기**: -7.3 → -6.0 ~ -6.5 (기질 약간 화면 아래로 숨기고 식재부 더 노출)
- **타깃 Y 오프셋 추가**: `targetYForDistance`에 +0.5~1.0 고정 오프셋을 더해 카메라가 조금 위를 향하게 → 물고기 중간 높이가 화면 중심에 오도록
- **비율별 다른 bottom offset**: 가로 바(aspect ≥ 1.5)에서는 기질을 더 숨기고 식재부 기준으로 프레이밍

> 주의: 카메라 빼기(거리 ↑)는 §1 D(코스틱·Bloom)와 §3(물고기 크기)에 연쇄 영향 → 빼기 후 베타 스케일과 프레이밍을 함께 재측정한다.

## 3. 물고기 크기·존재감

### 문제
베타 스케일이 원본(1.1)의 62%(현재 0.68)로, 480×320 위젯에서 너무 작아 인상적이지 않다.

### 아이디어

- **베타 스케일 업**: 0.68 → 0.85 ~ 0.90 (크기만 조정, 이동 속도는 유지)
- **베타 색상 농도**: 현재 `0xd32f2f`(Material Red 700)는 좋으나, 톤매핑 후 더 선명하게 하려면 `0xe53935` 또는 emissive 약간 추가
- **코리도라스 스케일**: 현재 0.65 → 0.70 (바닥 청소부 존재감)

## 4. UX · 인터랙션

### 4-1. 줌 리셋
- 더블클릭 또는 메뉴 옵션 → 자동 프레이밍 거리로 복귀 (`zoomDistance = null`)

### 4-2. 물고기 대사 톤·타이밍
- 현재 6초 노출 — 짧다는 의견 가능성 → 8초로 늘리거나 마우스 호버 시 유지 옵션
- 대사 수 증가: 종별 3줄 → 5줄 (반복감 감소)
- 베타: 홀로 사는 수컷의 철학적 독백 톤 강화

### 4-3. 트레이 아이콘 발견성 (KNOWN_ISSUES.md)
- 현재 노치 맥북에서 아이콘이 가려질 수 있음
- 후보: 더 굵고 단순한 물방울/물고기 글리프 + 여백 최소화

### 4-4. 창 배치 기억
- 이전 세션 창 위치·크기 영속화 (settings 스토어에 저장)
- 기본 위치: 우하단 고정 옵션

### 코드 구조 준비사항

- 공통 인터페이스 `{ group, update(delta, time) }` 이미 확립 → 새 생물은 이 계약만 구현

## 6. 사용량 연동 심화 (v2 핵심)

### 6-1. 한도 데이터 소스 (memory 참조)
- CC UI에 정밀값 존재 — 롤링 5h 근사보다 그 소스 먼저 조사 (project memory에 기록)
- 한도 임박(80%·95%) 시 어항 연동 시각 피드백 (물이 탁해지거나 물고기 행동 변화)

### 6-2. 어항 ↔ 사용량 시각 연동 아이디어
| 상태 | 어항 반응 |
|---|---|
| 여유(0~60%) | 맑은 물, 활발한 물고기 |
| 경고(60~80%) | 포그 밀도 미세 증가, 물고기 속도 약간 둔화 |
| 임박(80~95%) | 포그 색조 살짝 붉어짐, 물고기 군집 |
| 한계(95%+) | 포그 짙어짐, 코스틱 약해짐, 물고기 바닥으로 |

### 6-3. HUD 개선
- 컨텍스트 바: 숫자+퍼센트 외에 시각 바(얇은 선) 추가
- 한도 임박 시 HUD 강조 (opacity faint → bright 자동 전환)

## 7. 성능 (fast-follow, ADR-007)

- **rAF 스로틀**: 창 가림·포커스 없음 시 30fps로 제한
- **창 접힘(puck) 시 렌더 정지**: 현재 접혀도 rAF 계속 돌아감 → `document.hidden` 감지로 pause
- **Bloom 해상도**: 위젯 크기(480×320)에서 full-res Bloom은 과함 → 0.5x 해상도 옵션
