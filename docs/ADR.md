# Architecture Decision Records

## 철학
관상용 위젯 — 가볍고 항상 떠 있어도 부담 없어야 한다. 작업 화면을 가리지 않고, 메모리/CPU를 적게 쓰며, 사용량을 곁눈질로 읽을 수 있어야 한다. 기존 Three.js 프로토타입의 자산을 최대한 재사용한다.

---

### ADR-001: 데스크톱 셸로 Tauri v2 선택
**결정**: Electron이 아닌 Tauri v2로 데스크톱 셸을 구성한다.
**이유**: 상시 떠 있는 관상용 위젯은 메모리/용량 발자국이 작아야 한다. Tauri는 시스템 웹뷰를 써서 경량이고, 투명·always-on-top·프레임리스 창을 기본 지원한다. 기존 Three.js/웹 코드를 그대로 웹뷰에 이식 가능.
**트레이드오프**: Rust 빌드 체인·플랫폼별 웹뷰 차이를 감수. Electron 대비 생태계/예제가 적다.

### ADR-002: 사용량 데이터는 Claude Code 로컬 세션/로그에서, Rust에서만 읽는다
**결정**: 토큰·한도·컨텍스트 윈도우 수치를 로컬 Claude Code 세션/로그 파일에서 파싱하며, 파일 접근은 전부 Rust(`usage.rs`)에서 처리하고 웹뷰엔 IPC 이벤트로만 전달한다.
**이유**: 실제 작업과 연동된 실시간 수치 제공. 파일 접근을 Rust로 격리하면 Tauri capability 보안 모델을 지키고 렌더러를 순수하게 유지할 수 있다.
**트레이드오프**: Claude Code 로그 포맷/경로 변경에 취약 → 파서를 어댑터로 격리해 흡수. 비공식 로그 의존이므로 포맷 검증·폴백 필요.

### ADR-003: CDN 의존 제거, npm/ESM 번들로 전환
**결정**: 기존 `index.html`의 Three.js r128·Tailwind·FontAwesome CDN을 모두 npm 의존성(ESM)으로 옮기고 Vite로 번들한다.
**이유**: 데스크톱 앱은 오프라인에서 동작하고 재현 가능한 빌드여야 한다. 버전 고정·트리셰이킹·타입 지원 확보.
**트레이드오프**: 초기 마이그레이션 비용(전역 `THREE` → import, 빌드 셋업). r128 → 최신 Three.js API 변경 일부 수정 필요.

### ADR-004: 프론트 프레임워크 없이 vanilla TS + 경량 반응 스토어
**결정**: React/Vue 등 UI 프레임워크를 도입하지 않고 vanilla TypeScript + 경량 스토어(nanostores 또는 EventTarget)로 HUD를 구성한다.
**이유**: 화면 콘텐츠는 명령형 Three.js 씬이 대부분이고, HUD는 작은 오버레이뿐. 프레임워크는 과한 무게.
**트레이드오프**: 복잡한 UI가 늘면 직접 만든 반응 레이어의 유지비가 커질 수 있다. 그 시점에 재평가.

### ADR-005: 트레이 아이콘을 위젯의 1차 컨트롤 표면으로
**결정**: 프레임리스·무(無)크롬 창이므로 표시/숨김·종료·설정 진입을 전부 트레이(메뉴바) 아이콘으로 제공한다.
**이유**: 닫기 버튼이 없는 always-on-top 위젯은 트레이 없이는 종료·복귀가 불가능하다. 트레이가 사실상의 메인 메뉴.
**트레이드오프**: 트레이 메뉴 의존도가 높아져 발견성이 떨어질 수 있다 → 첫 실행 시 짧은 안내로 보완.

### ADR-006: 클릭 통과는 토글, 기본값은 '입력 수신'
**결정**: 마우스 클릭 통과(mouse passthrough)를 토글로 제공하되, 기본값은 입력을 받는 상태로 둔다.
**이유**: 기본 통과로 두면 사용자가 위젯을 클릭(밥주기·감상)할 방법을 잃고 혼란. 일할 때만 통과로 바꾸는 모델이 안전.
**트레이드오프**: 처음엔 위젯이 클릭을 가로채 작업에 거슬릴 수 있음 → 트레이/단축키로 빠르게 통과 전환 가능하게.

### ADR-007: 상시 구동 리소스 예산은 후속 과제로 명시
**결정**: 가림/포커스/배터리 감지 기반 FPS 저감·일시정지(리소스 스로틀)는 MVP에서 제외하고 fast-follow 1순위로 둔다.
**이유**: 사용자가 MVP 범위에서 뺐다. 단, 종일 구동 위젯의 팬·배터리 부담은 실사용 만족도를 좌우하는 실질 위험이므로 기록해 추적.
**트레이드오프**: MVP는 전력 효율이 떨어진 상태로 출시될 수 있음. 초기 사용 피드백에서 최우선으로 다룬다.

### ADR-008: 보안 자세 — 완전 로컬, 무(無) 네트워크, 최소 권한
**결정**: 앱은 어떤 네트워크 송신도 하지 않는다. 텔레메트리/분석/자동업데이트 OFF, CSP `connect-src 'none'`, 모든 자산 번들. FS 권한은 `~/.claude/**` 읽기 전용 + 설정 쓰기는 앱 config 디렉토리로 한정. IPC는 숫자 집계만 내보내고, Rust command는 호출자 경로 인자를 받지 않는다.
**이유**: Claude Code 로그엔 프롬프트·코드·잠재적 비밀이 포함된다. 데이터가 단 한 바이트도 기기 밖으로 나가지 않음을 설계로 보장해야 사용자가 안심하고 상주시킨다.
**트레이드오프**: 자동업데이트·원격 설정·사용 통계 수집을 포기. 업데이트는 수동 배포, 개선은 로컬 피드백에 의존.

### ADR-009: 사용량 읽기 실패 격리 — 어항은 항상 산다
**결정**: 사용량 파싱은 best-effort로 취급한다. 로그 부재·포맷 드리프트·잘린 줄·알 수 없는 모델·권한 오류는 해당 줄/파일만 skip하고, HUD는 "데이터 없음" 상태로 떨어진다. 파서는 panic/throw하지 않는다.
**이유**: 비공식 로그 포맷에 의존하므로 깨질 수 있다. 그래도 핵심 가치(관상용 어항)는 외부 데이터와 무관하게 항상 동작해야 한다.
**트레이드오프**: 일시적으로 부정확하거나 빈 수치를 보일 수 있음. 정확도보다 가용성·무중단을 우선한다.

### ADR-010: 미학이 1차 가치 — 시각 품질 게이트는 1급 시민
**결정**: 관상이 제품의 핵심 가치이므로, 씬을 건드리는 step은 실행형 AC(build/test) 통과만으로 완료되지 않는다. `docs/AESTHETIC.md`의 루브릭에 따라 결정론적 캡처를 산출하고, **게이트1(designer 에이전트 루브릭 자동 리뷰) → 게이트2(사용자 사인오프)** 를 통과해야 `completed`. 시네마틱 렌더는 **점진·목표기반**으로 구현 — 핵심 패스(톤매핑·색관리·코스틱·은은한 Bloom)부터 넣고 루브릭/60초 물멍 테스트로 판단해 DoF·갓레이는 필요할 때만 추가(목록대로 6패스 일괄 금지). 아트 디렉션은 `sample.jpeg`에서 도출. 루브릭은 이진 체크 가능 항목 위주로 좁히고, 진짜 주관적 판단만 사용자 게이트에 맡긴다.
**이유**: 측정·게이트 없는 미학은 반드시 후순위로 밀려 "기능은 되는데 안 예쁜" 제품이 된다. 가장 중요한 가치에 가장 강한 게이트를 둔다. 점진 구현은 거대한 튜닝 표면·성능비용을 한 번에 떠안는 것을 피한다.
**트레이드오프**: step 완료가 느려지고(캡처+이중 리뷰+반복) 사용자 개입이 늘며 시네마틱 파이프라인의 성능 비용이 있다. 그래도 1차 가치를 지키는 비용으로 수용.

### ADR-011: 큰 가정은 버리는 스파이크로 선(先)검증 (verify before build)
**결정**: 본 구현 전에 throwaway 스파이크 2개로 핵심 가정을 검증한다 — ①로그 파싱 결과(컨텍스트%·토큰)를 Claude Code 실제 `/usage`와 눈으로 대조 ②Tauri 창 능력(투명·always-on-top·클릭통과·트레이) 최소 확인. 통과하면 진행, 어긋나면 설계(특히 한도 근사 방식)를 고친다.
**이유**: 사용량 아키텍처 전체가 "JSONL로 한도/컨텍스트를 의미있게 근사 가능"이라는 미검증 가정 위에 있었다. 가장 리스크 큰 가정을 가장 싸게 먼저 깬다.
**트레이드오프**: 착수가 약간 늦어지지만, 잘못된 가정 위에 큰 구조를 쌓고 되돌리는 비용을 회피한다.

### ADR-012: 크리티컬패스 우선 — v1(폴리시된 관상)과 v2(연동·심화) 분리
**결정**: v1 = 폴리시된 어항 + 기본 HUD(현재 세션 컨텍스트%·토큰) + 트레이 + 클릭통과. v2 = 한도 근사·사용량↔어항 연동·새우/가재·인터랙션·comfort(드리프트/Zen)·정식 도킹. (리소스 스로틀은 fast-follow.)
**이유**: 세 개의 큰 워크스트림(연동·시네마틱·comfort)을 한 MVP에 묶으면 1차 가치(아름다운 관상)의 출시가 늦어진다. 가장 핵심인 "예쁜 상시 어항"을 먼저 손에 쥐고 깊이를 쌓는다.
**트레이드오프**: 클러버한 연동·물멍 모드가 v1엔 없음. 단, 곁눈질 기본 정보와 관상 가치는 v1에서 이미 충족.
